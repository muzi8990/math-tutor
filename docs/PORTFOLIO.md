# 项目讲解提纲

本文件帮助介绍项目的真实设计与工程取舍。简历中的贡献应对应本人实际承担并能够解释的工作，不将原项目或 AI 辅助生成的部分全部描述为独立原创。

## 一分钟介绍

这是一个面向小学数学的多模态辅导后端。我关注的不只是模型返回答案，还包括结构化知识点、步骤关联、质量核验，以及错题从收录到重做和复习的闭环。系统以 FastAPI 提供接口，Pydantic 定义输出契约，Gemini 负责图片和语言理解，SQLite 保存错题与可恢复任务。当前完成了离线回归验证，真实教学效果还需要题集和学生实验验证。

根据实际参与情况调整这段介绍中的第一人称。

## 可以演示的流程

1. 启动 API，在 Swagger 上传一道清晰的题目图片，查看知识点、步骤和引用关系。
2. 创建普通会话，追问某一步，让系统提示而非仅给最终结果。
3. 启动 worker、启用本地身份，收录错题并查询分析状态。
4. 创建练习、请求提示、提交作答，查看诊断、独立完成记录和复习安排。
5. 运行离线测试，讲解模型请求失败、结构非法或无法可靠确认时的处理。

实时演示需要本人账号可用的 Gemini 模型与密钥。没有模型权限时，可演示离线测试和阅读测试样例，不将模拟响应当成实时生成。

## 值得解释的技术问题

| 面试问题 | 可讲解的实现 | 阅读入口 |
| --- | --- | --- |
| 如何约束 LLM 输出？ | 原生 JSON Schema + 本地关系校验，区分结构有效与答案正确 | `analysis.py`, `agent.py` |
| 为什么还要质量检查？ | 精确数值检查、风险复核、一次修复和待确认降级 | `quality.py`, `test_quality.py` |
| 后台任务如何避免旧结果覆盖？ | 租约、题目版本及提交时再次校验 | `mistakes/worker.py` |
| 重复提交如何处理？ | 持久化幂等键、输入摘要、处理租约 | `mistakes/service.py` |
| 学生用了提示如何统计？ | 服务端记录提示次数，区分独立和辅助完成 | `mistakes/service.py` |
| 为什么选择 SQLite？ | 本地首期部署成本低，承认单机与扩展边界 | `mistakes/database.py` |
| 如何测试模型应用？ | 注入客户端、真实 SDK + 模拟 HTTP、ASGI 接口测试 | `tests/` |
| 如何保护学习数据？ | 学生范围授权、私有资源读取、日志脱敏；完整账号系统未实现 | `mistakes/identity.py`, `logging.py` |
